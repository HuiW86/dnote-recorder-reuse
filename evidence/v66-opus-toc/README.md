# V66 Opus 帧头（TOC）统计

**对应** #66　**状态** 单卡取得短、长样本的部分真机证据，场景明确的样本和其他卡待测

## 要回答的问题

卡上的音频被按「固定 40 字节一帧、每帧 20 ms、单声道」切帧。固件 v1.50 的真实录音里，每 40 字节的第一个字节（Opus 包头 TOC，RFC 6716 §3.1）是否都表示「一包一帧、20 ms、单声道」？

## 命令

用已经拉到电脑上的原始文件（`pull` 会在输出目录留下 `<文件名>.raw`），不需要连卡：

```bash
cd client && source .venv/bin/activate
python dnote.py toc ./recordings/*.raw | tee ../evidence/v66-opus-toc/toc-v1.50.txt
```

输出里只有文件名、帧数和帧头统计，没有 `sn` 和蓝牙地址，可以直接入库。原始音频不入库（硬规则 4）。

## 样本要求

- 至少 3 个文件：一条 1 分钟以内的、一条 30 分钟以上的、一条按键发起的
- 至少一条有人说话、一条基本安静（编码器在静音时可能换模式）
- #8 的另外几张卡各取一条，单独存成 `toc-<固件版本>-<sn 摘要前 8 位>.txt`

## 判据

| 结果 | 结论 |
|---|---|
| 每个文件都是 `matches 20 ms mono: yes` | 假设成立。把看到的 TOC 取值写进 `docs/PROTOCOL.md` §6.1，然后把检查接进同步（#66 第 2、3 步） |
| 有文件是 `NO`，但 OGG 能正常播放 | 检查规则太严，按实际取值修改 `opus_frames_match_card_format` 和 Swift 的 `OpusTOC`，再接进同步 |
| 有文件是 `NO`，且 OGG 播放异常 | 该固件的帧格式不同，按帧头重新切帧；在此之前这类文件不入库、不删卡上文件 |

## 已有的非真机结果

- 随机字节（测试样本 `plain.bin`）不通过检查：符合预期
- 系统编码器按卡的参数（16 kHz 单声道、20 ms）产生的包：由 `OpusTOCTests.systemEncoderPacketsPass` 在 CI 的 macOS 上验证

## 结论

### 固件 v1.50 单卡备份（2026-11-25）

用 [T-M1-56 的 Mac 本地备份](../v42-t-m1-56/README.md) 复核卡 `7036aa3b` 的 48 段录音。iPhone 16 使用 iOS 27.0，连接过构建 109。此处数据来自 Mac 蓝牙下载，扫描时卡电量 100%，录音原始场景、电源状态未留档。

当前源码的 `client/dnote.py pull` 解密后把每 40 字节直接封装为一个 Ogg Opus 包。把下列命令得到的包字节依原顺序写到本机临时目录，再运行 `client/dnote.py toc`。例如对单个样本：

```sh
ffmpeg -nostdin -v error -i "$ogg" -map 0:a:0 -c:a copy -f data "$frames"
python client/dnote.py toc "$frames"
```

把本地备份按文件名排序编号，校验了 48 个输入文件的 SHA-256，均与 [备份清单](../v42-t-m1-56/card-backup-sha256.txt) 一致。解封装未重编码，48 个帧数与下载日志的帧数匹配，下载日志均未报告余字节。逐条原始统计包括序号、完整帧数、解封装余字节、现行规格判定、各 TOC 的计数和输入 SHA-256。[统计输出](toc-v1.50-backup-ogg.txt)

**部分通过。** 共 210,500 帧，`0x48` 出现 62,389 次，`0x4B` 出现 148,111 次。48 段都满足现行 20 ms 单声道检查。最长约 18 分 20 秒；仍缺 ≥30 分钟的原始卡文件、有明确录音方式和声音场景的样本，以及其他卡取样。

### 固件 v1.50 的 31 分 21 秒样本（2026-11-26，设备时间）

同卡由 DEBUG 109 在 iPhone 16 / iOS 27.0 上发起录音。录制期间暂停约 39 秒再继续，完整 BLE 同步，卡电量约 81% → 77%，手机 USB 供电。用上述 `ffmpeg -c:a copy` 方法从已存入的 OGG 无重编码解封装，再跑同一 `dnote.py toc`。94,050 帧全部匹配现行 20 ms 单声道检查，余 0 字节，其中 `0x48` 24,364、`0x4B` 69,686。来源 OGG 的校验值与 App 数据库一致。见 [长样本输出](toc-v1.50-long-ogg.txt) 和 [传输及文件证明](../v42-long-card-recording/README.md)。

加入长样本后共计 304,550 帧。当前证据来自 OGG 无重编码解封装，没有对这条录音另取 Mac BLE 下载的原始文件。仍缺标明按键发起、有人讲话和基本安静的样本及其他卡，整体结论仍为部分通过。
