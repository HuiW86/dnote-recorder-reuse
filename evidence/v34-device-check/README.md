## 1. `0x81` 开关状态（`switches.jsonl`）

**判据**：逐项设置（`0x83`、`0x84`、`0x85`、`0x8B`、`0x8C`、`0x8D`、`0x8F`），0.5 s 后 `0x81` 读回新值，且其他字段不变；之后恢复原值并读回确认。

**结果：通过（7/7）**

- 出厂值：`{"ms":0,"led":1,"motor":1,"nc":1,"wav":0,"vad":0,"gain":4,"nn":4,"autoff":600}`，字段名与 `PROTOCOL.md` 中按固件模板推测的一致。
- 每项读回值都等于设置值，`changed_fields` 只有对应的一个字段；7 项全部恢复成原值。
- 每条设置命令都回 1 字节 `0x01`（例如 `a0830101`）。
- 未验证：`ms`（`0x82` USB 存储）、`wav`（`0x8A` 保存 WAV），二者属于 M4（`features.md` A3b）。

## 2. 暂停与继续（`pause.jsonl`）

**判据**：录 10 s → `0x52` 暂停 10 s → `0x53` 继续 10 s → `0x50` 停止。下载解密后按 40 字节/帧计算时长：约 20 s 说明暂停有效，约 30 s 说明无效。

**结果：通过，暂停有效**

| 时刻 | 事件 |
|---|---|
| 0.4 s | `0x51` 回 `{"name":"20261106215528.opus"}` |
| 10.5 s | `0x52` 回 `0x01` |
| 11.5 s | `0x56`：`size 18000, recd 9000, rec 2` |
| 20.6 s | `0x53` 回 `0x01` |
| 21.6 s | `0x56`：`size 20000, recd 10000, rec 1` |
| 30.7 s | 设备推送 `0x56 rec 0`，随后 `0x50` 回 `0x01` |

- 文件 38,060 字节，解密后 950 帧 = **19.0 s**（预期暂停有效 20 s、无效 30 s），可正常解码。
- **新发现**：暂停期间 `0x56` 的 `rec=2`。文档原先只记录了 0 和 1。
- `recd` 与 `size` 的比例为 1 : 2（2,000 字节/秒），推测 `recd` 是已录时长，单位毫秒。
- 未测：暂停期间 `0x90` 文件列表的行为；暂停状态下直接 `0x50` 停止。

## 3. 断点续传（`offset.jsonl`）

**判据**：以完整下载为基准，① 同一连接内用非 0 offset 下载，结果等于基准从 offset 起的部分；② 下载到一半断开，重连后用已收字节数续传，拼接结果的 sha256 等于基准。

**结果：通过**

| 步骤 | 结果 |
|---|---|
| 完整下载 | 948,060 字节，4,741 个分片，sha256 `6806825ab1f6abd7…`，用时约 42 s |
| 同连接，offset 474,030（200 字节对齐） | 首个分片 offset = 474,030；内容等于基准尾部 |
| 同连接，offset 474,043（不对齐） | 首个分片 offset = 474,043；内容等于基准尾部 |
| 收到 474,200 字节后断开 | — |
| 新连接，offset 474,200 续传 | 拼接后 948,060 字节，sha256 与基准一致 |

- 每个分片数据为 200 字节，`offset` 是该分片在文件中的位置。
- 下载中途断开后，卡可以正常重连，续传正常。
