## 模拟复现与修复

基于 `6330d2f` 的隔离源码快照，用 FakeCard 创建一次下载失败，将该文件从模拟卡列表移除，重试延迟改为 250 ms。一秒内列表请求至少 3 次；数据库失败项的 attempts 仍为 1，而可见失败计数为 0。测试仅作用于模拟卡，证明此代码路径可以无限空重试，不证明真机的具体触发源就是它。

修复使自动重试候选同时满足「本轮列表含相同文件名和大小」与「仍可重试」；完成新检查并获取列表后替换旧计时器，计时器醒来时核对设备连接及身份；完成前核对卡未切换。新增脱敏的请求来源、排队状态、列表数、候选数和可重试数日志，便于真机区分触发链。

运行 `cd app/ReviveKit && swift test --disable-xctest`，所有测试套件通过；其中 SyncEngineTests 35 项通过，覆盖文件消失、再次出现、同名不同大小、旧定时器取消及诊断计数。`scripts/check-m1-rules.sh` 与 `git diff --check` 通过。测试使用本机缓存的 GRDB，未更改依赖版本。

### 代码审查补充

审查发现构建 (4) 的实现会在新请求开始时立即取消旧重试计时器；如果该请求在获取文件列表前超时，原先可重试的文件可能失去自动重试机会。模拟卡新增 `failedManualListDoesNotLoseScheduledRetry`：构建 (4) 的逻辑失败，改为仅在新检查成功完成且获取了新列表之后替换计时器，该用例通过。修复后 SyncEngineTests 36 项、完整 `swift test --disable-xctest` 和 `scripts/check-m1-rules.sh` 均通过。上述真机运行针对构建 (4)，不包含此后追加的计时器边界修复；最终提交尚需真机复验。
