# #79 同步重试循环

## 基线与真机观察

- iPhone 16 / iOS 27.0；TestFlight 闻笺 0.1.0 (2)，归档源码 `6330d2f`；一张固件 1.50 录音卡。
- 手机本地时间 2026-11-17 14:34:32–14:35:19：14:34:37 显示「正在检查录音卡…」，14:34:43 显示完成提示，14:35:04 显示完成时间 14:35；录音列表始终 31 条。未抓到完整触发链、下载协议或本机同步数据库。
- 导出的旧版诊断日志有较早的蓝牙断线，但没有记录该观察期的同步触发。旧日志不是所有检查的完整审计；不以缺失记录断定没有事件。

## 模拟复现与修复

基于 `6330d2f` 的隔离源码快照，用 FakeCard 创建一次下载失败，将该文件从模拟卡列表移除，重试延迟改为 250 ms。一秒内列表请求至少 3 次；数据库失败项的 attempts 仍为 1，而可见失败计数为 0。测试仅作用于模拟卡，证明此代码路径可以无限空重试，不证明真机的具体触发源就是它。

修复使自动重试候选同时满足「本轮列表含相同文件名和大小」与「仍可重试」；新检查取消旧计时器，计时器醒来时核对设备连接及身份；完成前核对卡未切换。新增脱敏的请求来源、排队状态、列表数、候选数和可重试数日志，便于真机区分触发链。

运行 `cd app/ReviveKit && swift test --disable-xctest`，所有测试套件通过；其中 SyncEngineTests 35 项通过，覆盖文件消失、再次出现、同名不同大小、旧定时器取消及诊断计数。`scripts/check-m1-rules.sh` 与 `git diff --check` 通过。测试使用本机缓存的 GRDB，未更改依赖版本。
