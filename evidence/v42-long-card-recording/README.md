## 判据和步骤

1. `test-spec.md` §3.4 要求录音达到 30 分钟、完成蓝牙同步，下载吞吐与约 24 KB/s 基线偏差不超过 20%（19.2–28.8 KB/s）。暂停和继续可用时，要核对接合处的音频连续性。
2. 保持「同步后删除卡上录音」关闭，从闻笺开始一条卡录音。约录满 57 秒后暂停，等待约 39 秒，继续。让实际录音时间超过 30 分钟，再点「停止」，保留卡上文件。同步过程中闻笺保持前台，未人为断线。
3. 用 `xcrun devicectl device copy from --domain-type appDataContainer --domain-identifier com.huiw86.revive` 从手机复制 `Documents/card-debug.log` 和 `Library/Application Support/library` 到本机私有目录。截取设备时间 14:27:45–15:04:11 的协议日志，运行 #137 的 `python3 client/check_log.py <节选>`。
4. 在库的 `recording` 表按 `card_file_name` 查 `duration_ms`、`audio_path`、`audio_sha256`。校验本地 OGG 的 SHA-256，用 `ffprobe -show_entries format=duration,size:stream=codec_name,channels` 检查长度和编码，再用 `ffmpeg -v error -i "$ogg" -f null -` 完整解码。另解码 56.5–58.0 秒为 48 kHz 单声道 PCM，按每 0.5 秒统计样本数和 RMS。

## 结论

- **T-M1-53 不通过。** 31 分 21 秒录音完整同步，吞吐 `3,762,060 / 1024 / 233.787 = 15.7 KB/s`，比 `24 KB/s` 基线低约 35%。#137 检查器将吞吐超界打印为 `NOTE`，其整体 `pass` 不代表本用例通过。当前只测了 DEBUG 109、单张 v1.50 卡和这一轮传输。
- **T-M1-54 部分通过。** 暂停、继续的卡端回包正确，继续写同一文件，文件时长排除了约 39 秒的暂停。解码后接合处前后各半秒都有 24,000 个样本和非零音量，接合点相邻采样差 8 个 PCM 单位。未用带已知语音的录音听辨接合，听感待补。
- **T-M15-53 部分通过。** App 发起路径的 `0x51`、卡端 `0x90` 清单、`0x70` 与本机 `card_file_name` 均为同一文件名。此处用 App 的原始 `0x90` 回包核对，未另用 Mac 命令列文件。卡键发起和录音中断线重连为独立子项。
