### 0.2 组件词汇表

模板中的通用组件对应到 SwiftUI：

| 规范名称 | SwiftUI 实现 | 用途 |
|---|---|---|
| Modal | `.alert` | 需要确认的操作、阻断性错误 |
| ActionSheet | `.confirmationDialog` | 多选一（如删除确认） |
| Sheet | `.sheet` + `presentationDetents` | 设备切换、录音前确认、扫描 |
| Toast | 自定义浮层，顶部 2 s 自动消失；带一个操作按钮（「撤销」）的停留 5 s | 操作结果（「已移到最近删除」「设置失败」） |
| EmptyState | `ContentUnavailableView` | 无数据 |
| ErrorState | `ContentUnavailableView` + 操作按钮 | 页面级错误 |
| Banner | 列表顶部的一行提示 | 非阻断的持续状态（固件未验证、空间不足） |
| BottomBar | `.safeAreaInset(edge: .bottom)` | 首页底部录音控制、详情页底部播放条 |
| FullScreen | `.fullScreenCover` | 录音页（P13） |
| Notification | 本地通知 `UNUserNotificationCenter` | 后台同步存入新录音（X8，默认关） |

本项目自定义组件：

| 名称 | 位置 | 说明 |
|---|---|---|
| DeviceChip | 首页顶栏左侧 | 设备图标 + 名称 + 连接状态 / 电量 + 下拉箭头（PS:4.2 P05） |

### 0.3 约束（来自 `CLAUDE.md` 硬规则）

- 界面上**没有**任何触发 `0x93`、`0x94`、`0xB0`/`0xB1` 的入口；也不显示「固件更新」「恢复出厂」「格式化」这类选项（硬规则 1）。
- 删除卡上文件只由 SyncEngine 在「已存入」之后执行，界面不提供「删除卡上录音」（硬规则 2）。M1.5 的「不要」（X10）也不直接删卡：它只记下一条请求，卡上文件仍由 SyncEngine 在这条录音已存入手机、并且手机上确实还有这份音频之后才删（`prd.md` §5.5）。
- 本文所有页面都不需要登录和网络（硬规则 3）。隐私政策、权限说明随 App 内置。M1.5 的本机转写强制离线识别，本地通知不经过服务器，同样不联网。
- 界面文案、图标、App 名称不出现 D·NOTE、追觅、Dreame；只有「关于」页可以写「适用于 D·NOTE 录音卡」（硬规则 5）。
- 日志和界面不显示完整 `sn`；设备页显示序列号后 4 位（硬规则 4 的界面延伸）。

## 1. 产品定义

### 1.1 定位

给手上有 D·NOTE 录音卡、但官方后台已失效的人用的离线 App：不登录、不联网，就能配对、录音、把录音同步到手机、播放和导出。

M1.5 补的是录音到了手机之后的体验，同样不登录、不联网：删了能找回（最近删除）、能改名、导出别人打得开的 M4A、录音中标重点、后台同步完成时通知、刚录完的可以选「不要」、在手机上转成文字（试验，默认关）。依据见 `beanpod-evaluation.md` §4.6。

### 1.2 用户

| 画像 | 场景 | 痛点 | 目标 |
|---|---|---|---|
| 原卡用户 | 开会、访谈时用卡录音 | 官方 App 登录不上，卡变砖；卡上已有的录音拿不出来 | 卡重新能用；旧录音取回手机 |
| 多卡用户 | 一部手机管理几张卡 | 官方绑定列表依赖后台，离线时为空 | 本地切换几张卡 |

### 1.3 核心价值

| 要素 | 描述 |
|---|---|
| 核心价值 | 卡上的录音安全地到手机上，可播放、可导出 |
| 关键时刻 | 配对后第一次同步完成，列表里出现卡上的旧录音并能播放 |
| 完成标准 | 用户完成配对，且至少一条录音状态为「已存入」 |

## 2. 信息架构

### 2.1 页面层级

```
首次使用（没有已配对设备时）
  P01 欢迎与权限说明 → P02 连接引导 → P03 扫描与配对 ─┐
                                                      ▼
底部标签栏（1.3 起，#89）：[ 总览 ] [ 录音 ]  ●  [ 知识库 ] [ 录音卡 ]
  ├─ P15 总览            ── 待办 → P06（纪要栏）；最近的录音 → P06；未设置 AI 服务 → AI 服务设置
  ├─ P05 录音列表        ── 列表行 → P06；DeviceChip 名称 → 录音卡标签，箭头 → P08（Sheet）
  ├─ ● 录音键            ── 空闲：开始录音（首次先 P04）；录音中：打开 P13；卡没连上：提示，可改用手机录
  ├─ P16 知识库          ── 搜索结果 / 最近整理好的 → P06
  └─ P07 录音卡（标签根） ── 「切换」→ P08（Sheet）── 添加 → P02
                           └ 齿轮 → P09 设置
                                     ├─ P14 最近删除
                                     ├─ P10 关于
                                     ├─ P11 隐私政策
                                     └─ P12 权限说明
开始录音（录音键或卡上按键）→ P13 录音页（全屏）；收起后点录音键或 P05 的 RecordingStatusCard 再打开
P07 解绑（Modal 确认）→ 还有其他卡时显示下一张；没有时进入 P01
```

导航深度最多 3 层（P07 → P09 → P10 或 P14）。共 16 个页面或面板（M1 12 个，M1.5 加 P13、P14，1.3 加 P15、P16），全部离线可用。

### 2.2 导航模型

- **沿用官方**：首页就是录音列表，设备入口在左上角，下拉切换设备、添加设备（OW §2、§3.4）。
- **改进**：不用底部标签栏。官方底部是「文件 / 动作按钮 / 我的」，M1 去掉会员、模板等内容后，「我的」只剩设置和关于，所以改成首页右上角的齿轮。底部换成常驻的录音控制栏（PS:4.2 P05），录音操作一次点击就能完成，官方要先点中间按钮再从弹出面板里选。
  - **2026-11-17 补充（#74）**：改版第一步只换样子，导航不变：仍然没有标签栏，空闲时的「开始录音」换成右下角悬浮的圆形录音键，录音开始后进入全屏录音页 P13。
  - **2026-11-18（1.3，#89）**：改版第二步推翻「不用底部标签栏」。底部是「总览、录音 | ● | 知识库、录音卡」四个标签，正中是红色录音键，在每个标签上位置相同（用户 2026-11-18 决定，与 beanpod 的 iPhone 版一致）。理由：设备页、待办汇总和搜索都需要固定位置；录音操作仍是一次点击。设置从录音卡页右上角的齿轮进入。每个标签有自己的导航栈，切换标签不丢各自的位置。
  - 录音键的三种状态：空闲时是白点，点击开始录音（首次先 P04）；录音中或暂停时键里显示已录时长，点击回到 P13；卡没连上或正在连接时，点击弹出 ActionSheet「录音卡还没连上」，说明按住卡上录音键唤醒，并提供「用这部手机录」（X18）。正在发录音命令时键里转圈、不可点。
- 根页面用 `NavigationStack`；P04、P08 用 Sheet，P13 用全屏覆盖，P14 和 P10～P12 一样用 push；P03 在首次使用流程里用 push，从 P08「添加」进入时用 Sheet。
- 返回：系统返回按钮和右滑返回手势；P13 用左上角的收起按钮。

### 2.3 导航目标

```swift
// Illustrative, not implementation.
enum Route: Hashable {
    case recording(id: UUID)   // P06
    case device(id: UUID)      // P07
    case settings, about, privacy, permissions  // P09–P12
    case trash                 // P14
    case recordingSummary(id: UUID)  // P06 opened on 纪要 (from P15, P16)
}
```

页面之间只传 id，目标页自己从 Library 读数据（PS:4.4）。P13 不是导航目标：它是标签栏之上的全屏覆盖，和 P05 共用同一个页面状态（`HomeModel`）。「留着 / 不要」卡片（X10）也浮在所有标签之上。

### 2.4 内容模型

实体和字段以 `prd.md` §5 为准（`device`、`recording`、`sync_item`），本文不重复。界面另外需要以下派生数据：

| 数据 | 来源 | 用于 |
|---|---|---|
| 设备界面状态 | CardService 的连接状态、`0x56` 录音状态、SyncEngine 的 `SyncStatus` 合成（PS:5.1） | DeviceChip、RecordControlBar、SyncStatusCard |
| 待同步条数、本次第几条 | SyncEngine（**目前未公开**，#41 实现时补接口） | SyncStatusCard |
| 上次同步完成时间 | SyncEngine 或 `sync_item` 最近一次 `stored` 时间（**待补**） | SyncStatusCard 离线状态 |
| 本地录音条数 | Library | 列表标题；不含最近删除里的 |
| 正在录的卡上文件名 | `0x51` 回包或卡的 `recordingStarted` 推送，`0x56` 回包补 | 重点（X7）按它记；录音结束后作为「刚录完的那条」（X10） |
| 本次录音已标的重点数 | Library 的 `recording_mark`，按卡上文件名查 | P13「标重点 · N」 |
| 刚录完的那条 | 录音状态从录音中 / 已暂停变为空闲时记下（卡、文件名、已录时长） | KeepOrDiscardCard |

### 2.5 视觉约定（代替 `design-spec.md`）

> **2026-11-16**：本节已由 `docs/design-spec.md` 取代（#74）。下面是 M1 首个构建的做法，留作记录；无障碍的要求继续有效。

- 用 iOS 系统组件、系统字体和语义色；支持深色模式和动态字体，VoiceOver 能读出所有按钮和状态。
- 强调色：M1 用系统默认的 `accentColor`，不模仿官方的金棕色和黑色底栏。品牌视觉在上架前定（ADR-005）。
- 图标用 SF Symbols；设备图标用通用的卡片外形符号，不用官方的产品图。
- 布局参照官方：首页大标题「全部录音 (N)」、列表行两行（标题 / 时间 · 时长）、设备页按「通用 / 录音设置 / 其他」分组的圆角列表（`List` + `.insetGrouped`）。
- 动画只用系统默认转场；录音中的指示用 SF Symbols 的 `variableColor` 效果，开启「减弱动态效果」时改为静态图标。

## 3. 用户流程

### 3.1 首次使用

| 阶段 | 页面 | 用户操作 | 系统响应 | 组件 | 和官方的差异 |
|---|---|---|---|---|---|
| 打开 | P01 | 看说明，点「继续」 | 请求蓝牙权限 | — | **改进**：官方没有权限说明页（OW §3.2）；这里先说明用途再请求 |
| 权限被拒 | P01 | — | 显示「需要蓝牙权限」+「去设置」 | ErrorState | 对应 `bluetoothUnauthorized` |
| 蓝牙关闭 | P01/P03 | — | 显示「请打开蓝牙」 | ErrorState | 对应 `bluetoothOff` |
| 唤醒卡 | P02 | 按卡上录音键，白灯闪烁时松手，点「继续」 | 进入扫描 | — | **沿用**官方指引 |
| 扫描 | P03 | 等待；看到卡后点它 | 列出附近的卡（电量、固件版本） | — | 列出所有卡让用户选，避免多卡场景中连错别人的卡 |
| 没找到 | P03 | 点「再试一次」或「稍后」 | 15 s 没扫到时显示 | EmptyState | **沿用**官方「未找到设备」 |
| 连接与配对 | P03 | 等待 | 步骤文字：正在连接 → 正在读取信息 → 正在配对 | — | 配对是离线的（`prd.md` §3），不依赖后台 |
| 卡已被他人绑定 | P03 | 确认或取消 | Modal：「此卡已被其他设备绑定，重新绑定后原设备将无法管理此卡。卡上的录音不受影响。」 | Modal | 取消时 `pairCancelled`，回到 P03 列表，不提示错误 |
| 完成 | P03 | 点「开始使用」 | 回到 P05，立即开始同步 | — | 官方是「欢迎加入」弹窗；这里在 P03 页内显示完成状态 |

关键时刻：P05 的 SyncStatusCard 显示「全部录音已存入手机」，列表里出现卡上的旧录音。

### 3.2 主循环：录音 → 同步 → 回放

| 阶段 | 页面 | 用户操作 | 系统响应 |
|---|---|---|---|
| 开始录音 | P05 | 点右下角的圆形录音键（第一次会先弹 P04） | `0x51`；自动打开 P13 录音页；P05 上出现 RecordingStatusCard，控制栏变成「暂停 / 停止」 |
| 按卡上按键录音 | — | 按卡上录音键 | 收到 `recordingStarted`，界面同步变成录音中；App 在前台时同样自动打开 P13 |
| 标重点 | P13 | 点「标重点」 | 按卡上报的已录时长记一处重点，不向卡发命令（X7）；按钮下的文字变成「标重点 · N」 |
| 暂停 / 继续 | P13 或 P05 | 点「暂停」或「继续」 | `0x52` / `0x53`；显示「已暂停」，计时停住 |
| 停止 | P13 或 P05 | 点「停止」（或按卡上按键） | `0x50`；P13 自动关闭；P05 顶部出现 KeepOrDiscardCard（X10）；1 s 后自动同步（`prd.md` §4.4） |
| 同步 | P05 | 无需操作；可以下拉刷新 | SyncStatusCard 显示进度；每存入一条，列表里按天插入一行。App 不在前台、且打开了通知开关时，存入新录音后发一条本地通知（X8） |
| 回放 | P06 | 点列表行，点播放；或点「重点」「文字稿」里的一行 | 播放 OGG；系统不能直接打开时先解码，显示「正在准备播放」；点重点或文字稿的一行从那里开始播 |
| 导出 | P06 | 点分享，选「M4A（微信等大多数 App 可播放）」或「原始文件（OGG）」 | 系统分享面板；文件为 `<标题>.m4a` 或 `<标题>.ogg`（标题见 PS:4.2 P06「分享」） |
| 转文字 | P06 | 设置里打开「本机转写（试验）」后，点「转成文字」 | 在手机上离线识别，完成后显示带时间的文字稿（X9） |

### 3.3 支线流程

| 流程 | 入口 | 过程 | 备注 |
|---|---|---|---|
| 回到 App 自动重连 | 冷启动或回到前台 | 已配对的卡挂起连接；卡广播时系统自动连上，连上后校时并同步 | DeviceChip 显示「未连接」；控制栏提示「按住卡上的录音键，白灯闪烁后松手」 |
| 添加第二张卡 | P08「添加」 | P02 → P03（Sheet） | 完成后当前设备切换到新卡 |

- 显示「录音中」或「已暂停」和**已录时长**（时:分:秒），下面一行小字是开始时间（从卡上文件名解析）。
- 计时来源：卡的 `0x56` 回包里的 `recd`（已录毫秒数；`evidence/v7-ios/probe.log` 中相隔约 33 s 的两次查询，`recd` 增加 34000）。录音中每秒在本地加 1，暂停时停住；每次收到 `0x56`（连接后、开始/暂停/继续/停止后）用 `recd` 校正。重连后先读 `0x56` 再显示计时，读到之前只显示「录音中」。
- 先实现，再优化：暂停期间 `recd` 是否停止增长、长时间录音时本地计时与 `recd` 的偏差，都没有真机证据；真机验证后再决定是否定时轮询 `0x56` 校正。
- 依赖：CardService 的 `RecordingStatus` 目前没有解析 `recd`，实现页面时补上。
- 动态指示见 PS:2.5。

**KeepOrDiscardCard**（M1.5 X10；**改进**：官方和 M1 都要等同步完再去列表里删，卡上还留一份）：

- 出现：连接中的当前卡，录音状态从录音中或已暂停变成空闲时（App 里点停止、卡上按键停止、或保持连接时读状态发现已停止），记下这条的卡上文件名，在列表顶部显示 10 s。只对当前选中的卡出现。断开期间在卡上停止的录音不会出现这张卡片：断开时 App 不再记着录音状态，重连后读到空闲不算「刚录完」。
- 标题「刚录完一条 · 00:03:12」（时长是停止时卡上报的已录时间；不知道时只写「刚录完一条」）；说明「不要的话，同步到手机后会移到「最近删除」，并从录音卡上删除」；按钮「留着」「不要」。
- 「留着」或 10 s 不理：卡片消失，什么都不做。
- 「不要」：Toast「这条不会保留」带「撤销」，并立即请求一次同步。之后的行为见 PS:3.3「刚录完的不要」。失败时 Toast「操作失败，请重试」。
- 撤销：Toast「已保留」；失败时「恢复失败，请重试」。

- 失败：恢复失败「恢复失败，请重试」；删除失败「删除失败，请重试」；读不到列表「无法读取最近删除」。
- 空：EmptyState「没有最近删除的录音」/「在这部手机上删除的录音会在这里保留 7 天」。
- 到期清除：每次 App 启动时，删除满 7 天的（按删除时间算，不按自然日）。App 不启动就不会清除。
- 彻底删除和到期清除都不向卡发命令，也不会让这条录音再次同步回来（`prd.md` §4.3）。重点按卡上文件记，彻底删除录音时不删。
- 选了「不要」（X10）的录音也在这里，恢复它只恢复手机上这份：卡上的删除照常进行（见 §7.2）。

## 5. 设备状态与功能

### 5.1 状态

M1 没有账号，界面按「当前设备」的状态决定什么可用。

| 状态 | 含义 | 来源 |
|---|---|---|
| `noDevice` | 本地没有已配对设备 | Library |
| `waiting` | 已配对，未连接，挂起连接中 | CardLink `idle` / `disconnected` |
| `connecting` | 正在连接或连接后的初始化（读信息、校时） | CardLink `connecting` |
| `idle` | 已连接，没在录音 | `0x56` `rec = 0` |
| `recording` | 录音中 | `rec = 1` 或 `recordingStarted` |
| `paused` | 已暂停 | `rec = 2` |
| `bluetoothUnavailable` | 蓝牙关闭或没有权限，优先于以上状态 | CardLink `poweredOff` / `unauthorized` |

同步状态（`SyncStatus`）与以上状态并行，只在 `idle` 时运行（录音中为 `waitingForRecording`）。

### 5.2 状态转换

```
noDevice   + 配对完成          → idle        [开始同步]
waiting    + 卡广播被系统连上   → connecting  [读信息、校时]
connecting + 初始化完成         → idle / recording / paused（按 0x56）
idle       + 开始录音（App 或按键） → recording [同步暂停]
recording  + 暂停               → paused
paused     + 继续               → recording
recording/paused + 停止         → idle        [1 s 后同步]
任意已连接 + 断开               → waiting     [挂起连接；同步中的文件保留进度]
任意       + 解绑               → waiting（切到其他卡）或 noDevice
任意       + 蓝牙关闭 / 撤销权限 → bluetoothUnavailable；恢复后回到 waiting
```

### 5.3 功能可用性

| 功能 | noDevice | waiting | connecting | idle | recording | paused | bluetoothUnavailable |
|---|---|---|---|---|---|---|---|
| 浏览、播放、导出、删除本地录音 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 开始录音 | 否→添加 | 否（置灰） | 否 | 是 | — | — | 否 |
| 暂停 / 继续 / 停止 | — | 否 | 否 | — | 是 | 是 | 否 |
| 同步（含下拉刷新） | — | 否（Toast） | 否 | 是 | 等录音结束 | 等录音结束 | 否 |
| 修改卡设置 | — | 否（隐藏） | 否 | 是 | 是 | 是 | 否 |
| 解绑 | — | 否（置灰） | 否 | 是 | 否（置灰：「请先停止录音」） | 否 | 否 |
| 切换 / 添加设备 | 添加 | 是 | 是 | 是 | 切换前 Modal：「卡会继续录音，切回来后再同步」 | 同左 | 否 |
| 最近删除、恢复、彻底删除、重命名（M1.5） | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 导出 M4A、本机转写（M1.5） | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 标重点（M1.5） | — | — | — | — | 是（卡已报出已录时间后） | 否（置灰） | — |
| 「留着 / 不要」（M1.5） | — | 卡片已出现的照常可点 | 同左 | 停止后 10 s 内 | — | — | 同左 |
| 「不要」之后删卡上文件（M1.5） | — | 等下次连接后的同步 | 同左 | 下一次同步 | 等录音结束 | 等录音结束 | 等恢复 |

设置项在录音中可改，因为设置命令不影响录音（`prd.md` §2.3 只要求已配对）；如果真机验证发现有影响，改为录音中置灰。

本机转写在录音中也能用；手机同时录音（卡）、同步和识别时的耗电和速度未测。

## 6. 提示

~~M1 只有 App 内提示，不做推送和本地通知。~~ M1 只有 App 内提示；M1.5 加了一个**本地通知**（X8），默认关，在 P09 打开。仍然没有推送（不联网）。

| 类型 | 组件 | 例子 |
|---|---|---|
| 操作结果 | Toast | 设置失败、录音卡未连接、已恢复、已彻底删除 |
| 可撤销的操作结果（M1.5） | Toast + 「撤销」 | 「已移到最近删除」（P05 左滑删除）、「这条不会保留」（「不要」） |
| 需要确认 | Modal / ActionSheet | 解绑、删除、彻底删除、清空最近删除、重新绑定已被他人绑定的卡 |
| 持续状态 | SyncStatusCard、Banner | 同步进度、蓝牙已关闭、固件未验证 |
| 阻断 | ErrorState | 没有蓝牙权限 |
| App 不在前台时（M1.5） | 本地通知 | 「录音已同步」/「N 条新录音已存入手机」 |

- 同一时间最多显示一个 Toast，新的替换旧的。普通 Toast 2 s 后消失；带「撤销」的停留 5 s，点「撤销」后 Toast 立即消失，再显示结果（「已恢复」「已保留」）。Toast 出现时 VoiceOver 朗读其文字。
- 撤销只针对最近一次操作：删除了 A 再「不要」B，撤销的是 B。
- **本地通知**（X8）：
  - 条件：开关打开；一轮同步结束时 App 不在前台（包括正在切换、下拉通知中心等非活跃状态）；这一轮里存入了至少一条来自卡的新录音（选了「不要」、已移到最近删除的不算）。
  - 内容：标题「录音已同步」，正文「N 条新录音已存入手机」。几次同步只保留最新一条通知，不叠加。
  - 点通知只打开 App，不跳到具体录音（代码没有处理通知点击）。
  - 只在这部手机上产生，不经过服务器。一轮同步在前台开始、到后台才结束的，也会通知；在后台开始、回到前台才结束的，不通知。
  - 不允许通知时：开关打开不了（P09）；同步状态照旧只在 P05 的 SyncStatusCard 上。`features.md` X8 说「不允许通知时退回 App 内提示」，实际就是这个已有的卡片，没有新增提示。

| `firmwareUnverified` | P03、P07 | 此固件版本未经验证，如遇问题请反馈 | P03 行尾 ⚠；P07 FirmwareBanner | 不阻断（X1） |

### 7.2 其他异常

| 异常 | 处理 |
|---|---|
| 录音卡剩余空间 < 10% 且未开启同步后删除 | SyncStatusCard 提示（PS:4.2 P05） |
| 卡上文件名的时间和手机时区不一致 | 列表按卡上时间显示，不做换算；校时（`0x87`）用手机本地时间，之后的新录音会一致（HANDOFF 风险项） |
| 卡上文件名无法解析出时间 | 标题用同步时间，第二行注明「时间未知」 |
| 同一张卡被另一部手机绑走 | 下次连接时 `notPaired`，按 §7.1 引导重新配对 |
| 录音时长很长（数小时） | 列表时长按「X 小时 Y 分钟」显示；播放器进度条可拖动。导出 M4A 和本机转写要先整条解码，耗时未测（`test-spec.md` T-M15-56） |
| 卡上那份已删（「同步后删除」或「不要」），手机上这条又被彻底删除或到期清除 | 这条录音就没有了。P14 的确认文字「录音卡不受影响」说的是不向卡发命令，没有提醒「这可能是最后一份」（§7.5 第 1 条） |
| 选了「不要」的录音在 P14 被恢复 | 只恢复手机上这份；「不要」的请求还在，卡上文件照样会被删除。想连卡上那份一起留，要在 5 s 内点 Toast 的「撤销」 |
| 选了「不要」的录音在卡上删除之前就被彻底删除 | 卡上文件不删（手机上已经没有这份，硬规则 2），保留在卡上；不会再同步回来 |
| 转写中离开 P06 再回来 | 前一次转写仍在跑，新打开的 P06 又显示「转成文字」，可以再开一次；两次结果先后存入，后存的覆盖前面的 |

### 7.5 已知缺口（1.2 走查代码时发现，待定）

1. P14「彻底删除」「清空」的确认文字只说「录音卡不受影响」。卡上那份已被「同步后删除」或「不要」删掉时，这是最后一份，文字没有提醒。建议按这条录音对应的 `sync_item` 是否已是 `deletedOnCard` 改文案。
2. 从 P06 删除没有撤销 Toast（P05 左滑有）。
3. 本机转写把解码失败也报成「找不到这条录音的音频文件」（`OnDeviceTranscriber` 把 `decodedPCM` 的所有错误都映射成 `audioMissing`）。
4. 转写中重新进入 P06 可以再开一次转写（§7.2）。
5. 在 P14 恢复一条选了「不要」的录音，卡上那份仍会被删除（§7.2）。是否要在恢复时一并撤销请求，待定。
6. 通知权限没有写进 P11、P12（P10～P12 小节）。
7. `design-spec.md` §3 里没有实现的部分：录音行右侧的重点数、播放条的倍速和重点刻度、详情页的「文字稿 / 重点」分栏、录音页的声波和收起后的细条、设备条上的「已连接 · 电量」文字（实现上是状态圆点加电池图标）、同步状态平时收成一行小字（实现上仍是卡片）、筛选项。其中分栏和筛选项属于第二步。

**2026-11-19 核对（#85）**：第 1、5、6 条在 PR #84 修复；第 2～4 条已在 `main` 上修复（P06 删除经首页给出「撤销」；解码失败报「转写失败」而不是「找不到音频」；转写状态放在页面之外，重进 P06 不会再开一次）。第 7 条：重点数、倍速、重点刻度、筛选项、分栏（1.3 的「纪要 / 文字稿 / 改写」）已实现；设备条改为「已连接 · 电量」文字，同步状态只在同步进行中显示为卡片、其余时候是一行小字（#85 的后续 PR）；录音页声波和收起后的细条仍未实现，收起后由底栏录音键里的时长代替细条。

同一 PR 另外补上：卡断开时结束的录音，在同一张卡重连后补问「留着 / 不要」（不知道时长，标题只写「刚录完一条」）；后台同步只存了一条时，点通知直接打开它；系统设置里关掉通知后，回到 App 时开关跟着关；设置里的转写开关对已经打开的 P06 立即生效；导出文件按页面显示的标题命名（「11月7日 14.02.ogg」，不是存储的「2026-11-07 14.02」）。
