## 0. 约定

### 0.1 编号与引用

- 页面编号 `P01`～`P12`（§4.1）；组件用 §0.2 的规范名称。
- `PS:x` 指本文第 x 节；`prd §x`、`OW §x` 分别指 `prd.md`、`official-ui-walkthrough.md`。
- 错误码写成 `bluetoothOff` 这样的代码名，含义见 `prd.md` §6，界面处理见本文 §7.1。

### 0.2 组件词汇表

模板中的通用组件对应到 SwiftUI：

| 规范名称 | SwiftUI 实现 | 用途 |
|---|---|---|
| Modal | `.alert` | 需要确认的操作、阻断性错误 |
| ActionSheet | `.confirmationDialog` | 多选一（如删除确认） |
| Sheet | `.sheet` + `presentationDetents` | 设备切换、录音前确认、扫描 |
| Toast | 自定义浮层，顶部 2 s 自动消失 | 操作结果（「已删除」「设置失败」） |
| EmptyState | `ContentUnavailableView` | 无数据 |
| ErrorState | `ContentUnavailableView` + 操作按钮 | 页面级错误 |
| Banner | 列表顶部的一行提示 | 非阻断的持续状态（固件未验证、空间不足） |
| BottomBar | `.safeAreaInset(edge: .bottom)` | 首页底部录音控制栏 |

本项目自定义组件：

| 名称 | 位置 | 说明 |
|---|---|---|
| DeviceChip | 首页顶栏左侧 | 设备图标 + 名称 + 连接状态 / 电量 + 下拉箭头（PS:4.2 P05） |
| SyncStatusCard | 首页列表顶部 | 同步状态，见 PS:4.2 P05「同步状态卡片」 |
| RecordingStatusCard | 首页列表顶部 | 录音中 / 已暂停，见 PS:4.2 P05 |
| RecordControlBar | 首页 BottomBar | 开始、暂停/继续、停止，见 PS:4.2 P05 |
| PlayerCard | 录音详情 | 播放器，见 PS:4.2 P06 |
| FirmwareBanner | 设备页 | 未验证固件提示（X1） |

### 0.3 约束（来自 `CLAUDE.md` 硬规则）

- 界面上**没有**任何触发 `0x93`、`0x94`、`0xB0`/`0xB1` 的入口；也不显示「固件更新」「恢复出厂」「格式化」这类选项（硬规则 1）。
- 删除卡上文件只由 SyncEngine 在「已存入」之后执行，界面不提供「删除卡上录音」（硬规则 2）。
- 本文所有页面都不需要登录和网络（硬规则 3）。隐私政策、权限说明随 App 内置。
- 界面文案、图标、App 名称不出现 D·NOTE、追觅、Dreame；只有「关于」页可以写「适用于 D·NOTE 录音卡」（硬规则 5）。
- 日志和界面不显示完整 `sn`；设备页显示序列号后 4 位（硬规则 4 的界面延伸）。

## 1. 产品定义

### 1.1 定位

给手上有 D·NOTE 录音卡、但官方后台已失效的人用的离线 App：不登录、不联网，就能配对、录音、把录音同步到手机、播放和导出。

### 1.2 用户

| 画像 | 场景 | 痛点 | 目标 |
|---|---|---|---|
| 原卡用户 | 开会、访谈时用卡录音 | 官方 App 登录不上，卡变砖；卡上已有的录音拿不出来 | 卡重新能用；旧录音取回手机 |
| 多卡用户 | 一部手机管理几张卡 | 官方绑定列表依赖后台，离线时为空 | 本地切换几张卡 |

### 1.3 核心价值

| 要素 | 描述 |
|---|---|
| 核心价值 | 卡上的录音安全地到手机上，可播放、可导出 |
| 关键时刻 | 配对后第一次同步完成，列表里出现卡上的旧录音并能播放 |
| 完成标准 | 用户完成配对，且至少一条录音状态为「已存入」 |

## 2. 信息架构

### 2.1 页面层级

```
首次使用（没有已配对设备时）
  P01 欢迎与权限说明 → P02 连接引导 → P03 扫描与配对 ─┐
                                                      ▼
P05 首页：录音列表                                  ← 根页面
  ├─ DeviceChip ─点名称→ P07 设备页
  │             └点箭头→ P08 设备切换（Sheet）── 添加 → P02
  ├─ 齿轮 → P09 设置
  │           ├─ P10 关于
  │           ├─ P11 隐私政策
  │           └─ P12 权限说明
  ├─ 列表行 → P06 录音详情
  └─ RecordControlBar ─首次开始录音→ P04 录音前确认（Sheet）
P07 设备页
  └─ 解绑（Modal 确认）→ 回到 P05；没有其他设备时进入 P01
```

导航深度最多 3 层（P05 → P09 → P10）。M1 共 12 个页面或面板，全部离线可用。

### 2.2 导航模型

- **沿用官方**：首页就是录音列表，设备入口在左上角，下拉切换设备、添加设备（OW §2、§3.4）。
- **改进**：不用底部标签栏。官方底部是「文件 / 动作按钮 / 我的」，M1 去掉会员、模板等内容后，「我的」只剩设置和关于，所以改成首页右上角的齿轮。底部换成常驻的录音控制栏（PS:4.2 P05），录音操作一次点击就能完成，官方要先点中间按钮再从弹出面板里选。
- 根页面用 `NavigationStack`；P04、P08 用 Sheet，P03 在首次使用流程里用 push，从 P08「添加」进入时用 Sheet。
- 返回：系统返回按钮和右滑返回手势。

### 2.3 导航目标

```swift
// Illustrative, not implementation.
enum Route: Hashable {
    case recording(id: UUID)   // P06
    case device(id: UUID)      // P07
    case settings, about, privacy, permissions  // P09–P12
}
```

页面之间只传 id，目标页自己从 Library 读数据（PS:4.4）。

### 2.4 内容模型

实体和字段以 `prd.md` §5 为准（`device`、`recording`、`sync_item`），本文不重复。界面另外需要以下派生数据：

| 数据 | 来源 | 用于 |
|---|---|---|
| 设备界面状态 | CardService 的连接状态、`0x56` 录音状态、SyncEngine 的 `SyncStatus` 合成（PS:5.1） | DeviceChip、RecordControlBar、SyncStatusCard |
| 待同步条数、本次第几条 | SyncEngine（**目前未公开**，#41 实现时补接口） | SyncStatusCard |
| 上次同步完成时间 | SyncEngine 或 `sync_item` 最近一次 `stored` 时间（**待补**） | SyncStatusCard 离线状态 |
| 本地录音条数 | Library | 列表标题 |

### 2.5 视觉约定（代替 `design-spec.md`）

- 用 iOS 系统组件、系统字体和语义色；支持深色模式和动态字体，VoiceOver 能读出所有按钮和状态。
- 强调色：M1 用系统默认的 `accentColor`，不模仿官方的金棕色和黑色底栏。品牌视觉在上架前定（ADR-005）。
- 图标用 SF Symbols；设备图标用通用的卡片外形符号，不用官方的产品图。
- 布局参照官方：首页大标题「全部录音 (N)」、列表行两行（标题 / 时间 · 时长）、设备页按「通用 / 录音设置 / 其他」分组的圆角列表（`List` + `.insetGrouped`）。
- 动画只用系统默认转场；录音中的指示用 SF Symbols 的 `variableColor` 效果，开启「减弱动态效果」时改为静态图标。

## 3. 用户流程

### 3.1 首次使用

| 阶段 | 页面 | 用户操作 | 系统响应 | 组件 | 和官方的差异 |
|---|---|---|---|---|---|
| 打开 | P01 | 看说明，点「继续」 | 请求蓝牙权限 | — | **改进**：官方没有权限说明页（OW §3.2）；这里先说明用途再请求 |
| 权限被拒 | P01 | — | 显示「需要蓝牙权限」+「去设置」 | ErrorState | 对应 `bluetoothUnauthorized` |
| 蓝牙关闭 | P01/P03 | — | 显示「请打开蓝牙」 | ErrorState | 对应 `bluetoothOff` |
| 唤醒卡 | P02 | 按卡上录音键，白灯闪烁时松手，点「继续」 | 进入扫描 | — | **沿用**官方指引 |
| 扫描 | P03 | 等待；看到卡后点它 | 列出附近的卡（电量、固件版本） | — | 列出所有卡让用户选，避免多卡场景中连错别人的卡 |
| 没找到 | P03 | 点「再试一次」或「稍后」 | 15 s 没扫到时显示 | EmptyState | **沿用**官方「未找到设备」 |
| 连接与配对 | P03 | 等待 | 步骤文字：正在连接 → 正在读取信息 → 正在配对 | — | 配对是离线的（`prd.md` §3），不依赖后台 |
| 卡已被他人绑定 | P03 | 确认或取消 | Modal：「此卡已被其他设备绑定，重新绑定后原设备将无法管理此卡。卡上的录音不受影响。」 | Modal | 取消时 `pairCancelled`，回到 P03 列表，不提示错误 |
| 完成 | P03 | 点「开始使用」 | 回到 P05，立即开始同步 | — | 官方是「欢迎加入」弹窗；这里在 P03 页内显示完成状态 |

关键时刻：P05 的 SyncStatusCard 显示「全部录音已存入手机」，列表里出现卡上的旧录音。

### 3.2 主循环：录音 → 同步 → 回放

| 阶段 | 页面 | 用户操作 | 系统响应 |
|---|---|---|---|
| 开始录音 | P05 | 点「开始录音」（第一次会先弹 P04） | `0x51`；RecordingStatusCard 出现，控制栏变成「暂停 / 停止」 |
| 按卡上按键录音 | — | 按卡上录音键 | 收到 `recordingStarted`，界面同步变成录音中 |
| 暂停 / 继续 | P05 | 点「暂停」或「继续」 | `0x52` / `0x53`；状态卡显示「已暂停」 |
| 停止 | P05 | 点「停止」（或按卡上按键） | `0x50`；1 s 后自动同步（`prd.md` §4.4） |
| 同步 | P05 | 无需操作；可以下拉刷新 | SyncStatusCard 显示进度；每存入一条，列表顶部插入一行 |
| 回放 | P06 | 点列表行，点播放 | 播放 OGG；系统不能直接打开时先解码，显示「正在准备播放」 |
| 导出 | P06 | 点分享 | 系统分享面板，文件为 `<标题>.ogg` |

### 3.3 支线流程

| 流程 | 入口 | 过程 | 备注 |
|---|---|---|---|
| 回到 App 自动重连 | 冷启动或回到前台 | 已配对的卡挂起连接；卡广播时系统自动连上，连上后校时并同步 | DeviceChip 显示「未连接」；控制栏提示「按住卡上的录音键，白灯闪烁后松手」 |
| 添加第二张卡 | P08「添加」 | P02 → P03（Sheet） | 完成后当前设备切换到新卡 |
| 切换设备 | P08 | 点另一张卡 | 断开当前卡、挂起连接新卡；同步中切换时先 Modal 确认「同步会在下次连接时继续」 |
| 解绑 | P07「解绑此卡」 | Modal 确认 → `0xA0 [0]` → `0xA1` 确认 | **改进**：官方解绑会格式化卡（OW §3.7）；这里只解绑，卡上录音和已同步到手机的录音都保留。没连上卡时不能解绑（按钮置灰并说明） |
| 只删除本机记录 | — | M1 不提供 | 解绑必须和卡通信；卡丢失的情况放到 M2 以后再考虑 |
| 删除录音 | P05 左滑或 P06 菜单 | ActionSheet 确认 → 删除本地录音 | 不向卡发命令；已删除的录音不会再次同步回来（`prd.md` §4.3） |

### 3.4 中断恢复

| 中断 | 恢复方式 | 依据 |
|---|---|---|
| 配对途中断开或 App 被杀 | 回到 P03 重新开始；已绑定成功的会在下一次 `0xA1` 查询时直接识别为已配对，不重复绑定 | `prd.md` §3 |
| 同步途中断开 | SyncStatusCard 变成「已断开，连上后继续」；重连后从断点续传 | `prd.md` §4.3 |
| 同步途中 App 被杀 | 下次启动时未完成的文件从头下载；SyncStatusCard 不显示错误 | `prd.md` §4.3 |
| 录音中 App 被杀 | 卡继续录音；重连后读 `0x56` 恢复录音中状态 | B1 |
| 播放时来电或拔耳机 | 暂停播放，不自动恢复；PlayerCard 显示已暂停 | #40 |
| 首次使用流程中途退出 | 下次打开时，没有已配对设备就从 P01 开始；权限已授予时跳过请求 | — |

- 卡的名称：蓝牙名，加广播里 SID 的后 4 位用于区分；固件不在已验证表时在行尾显示 ⚠，点进去照常配对（X1）。

#### P04 录音前确认

- **沿用官方**：标题「录音前请确认」、说明「请先征得对方同意再开始录音，并避免录制敏感信息」、勾选框「我已征得对方同意」、「开始录音」按钮（勾选后可点）。
- 只在 App 内第一次点「开始录音」前显示一次，记在本地；按卡上按键录音不弹。

## 5. 设备状态与功能

### 5.1 状态

M1 没有账号，界面按「当前设备」的状态决定什么可用。

| 状态 | 含义 | 来源 |
|---|---|---|
| `noDevice` | 本地没有已配对设备 | Library |
| `waiting` | 已配对，未连接，挂起连接中 | CardLink `idle` / `disconnected` |
| `connecting` | 正在连接或连接后的初始化（读信息、校时） | CardLink `connecting` |
| `idle` | 已连接，没在录音 | `0x56` `rec = 0` |
| `recording` | 录音中 | `rec = 1` 或 `recordingStarted` |
| `paused` | 已暂停 | `rec = 2` |
| `bluetoothUnavailable` | 蓝牙关闭或没有权限，优先于以上状态 | CardLink `poweredOff` / `unauthorized` |

同步状态（`SyncStatus`）与以上状态并行，只在 `idle` 时运行（录音中为 `waitingForRecording`）。

### 5.2 状态转换

```
noDevice   + 配对完成          → idle        [开始同步]
waiting    + 卡广播被系统连上   → connecting  [读信息、校时]
connecting + 初始化完成         → idle / recording / paused（按 0x56）
idle       + 开始录音（App 或按键） → recording [同步暂停]
recording  + 暂停               → paused
paused     + 继续               → recording
recording/paused + 停止         → idle        [1 s 后同步]
任意已连接 + 断开               → waiting     [挂起连接；同步中的文件保留进度]
任意       + 解绑               → waiting（切到其他卡）或 noDevice
任意       + 蓝牙关闭 / 撤销权限 → bluetoothUnavailable；恢复后回到 waiting
```

### 5.3 功能可用性

| 功能 | noDevice | waiting | connecting | idle | recording | paused | bluetoothUnavailable |
|---|---|---|---|---|---|---|---|
| 浏览、播放、导出、删除本地录音 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 开始录音 | 否→添加 | 否（置灰） | 否 | 是 | — | — | 否 |
| 暂停 / 继续 / 停止 | — | 否 | 否 | — | 是 | 是 | 否 |
| 同步（含下拉刷新） | — | 否（Toast） | 否 | 是 | 等录音结束 | 等录音结束 | 否 |
| 修改卡设置 | — | 否（隐藏） | 否 | 是 | 是 | 是 | 否 |
| 解绑 | — | 否（置灰） | 否 | 是 | 否（置灰：「请先停止录音」） | 否 | 否 |
| 切换 / 添加设备 | 添加 | 是 | 是 | 是 | 切换前 Modal：「卡会继续录音，切回来后再同步」 | 同左 | 否 |

设置项在录音中可改，因为设置命令不影响录音（`prd.md` §2.3 只要求已配对）；如果真机验证发现有影响，改为录音中置灰。

## 7. 异常

### 7.1 错误码的界面处理

覆盖 `prd.md` §6 的全部 21 个错误码（#41 验收）。「重试」指界面上的按钮；「自动」指 SyncEngine 或 CardService 自己处理，界面只显示状态。

| 错误码 | 出现在 | 文案 | 组件 | 恢复 |
|---|---|---|---|---|
| `bluetoothOff` | P01、P03、P05 | 蓝牙已关闭，请在控制中心或设置中打开 | ErrorState（P01/P03）/ Banner（P05） | 打开蓝牙后自动恢复 |
| `bluetoothUnauthorized` | P01、P03、P05 | 需要蓝牙权限才能连接录音卡 | ErrorState + 「去设置」 | 授权后回到 App 自动恢复 |
| `bluetoothUnsupported` | P01、P03 | 蓝牙暂时不可用，请稍后再试 | ErrorState + 「重试」 | 重试 |
| `connectTimeout` | P03、P05 | 连接超时。按住卡上的录音键，白灯闪烁后重试 | P03 步骤内错误 + 「重试」；P05 只更新 DeviceChip | 重试；P05 继续挂起连接 |
| `connectFailed` | P03、P05 | 同 `connectTimeout` | 同上 | 同上 |
| `unknownCard` | P05、P08 | 找不到这张录音卡，请重新搜索 | Modal +「重新搜索」→ P02 | 重新扫描并连接，不需要重新配对 |
| `disconnected` | P05、P07 | 连接已断开，连上后继续 | SyncStatusCard / DeviceChip | 自动挂起连接；同步自动续传 |
| `requestTimeout(cmd)` | P03、P05、P07 | 配对：录音卡没有响应，请重试；P07 设置：设置失败，请重试；P05 录音控制：对账后仍不确定时「录音卡没有响应，录音状态未确认」，确认命令未生效时「录音卡没有响应，请重试」；P05 单个文件下载：计入「N 条录音同步失败」；P05 整次同步：录音卡没有响应，请重试 | P03 步骤错误；P07 Toast；P05 录音控制 Toast；P05 同步 SyncStatusCard | 配对：「重试」；设置：自动重试 1 次后再提示；录音控制：不重发命令。超时后自动读一次 `0x56` 对账，读完前控制栏保持禁用；卡已到命令的目标状态就按卡更新、不提示，确认未生效才提示重试；`0x56` 也读不到时不引导用户重复操作（第一次可能已生效、只是回包丢失），之后的 `0x80` 与当前状态不一致时再读 `0x56` 修正（#47）；单个文件：同 `transferFailed`；整次同步：同 `storeFailed` 整次中断 |

### 7.2 其他异常

| 异常 | 处理 |
|---|---|
| 录音卡剩余空间 < 10% 且未开启同步后删除 | SyncStatusCard 提示（PS:4.2 P05） |
| 卡上文件名的时间和手机时区不一致 | 列表按卡上时间显示，不做换算；校时（`0x87`）用手机本地时间，之后的新录音会一致（HANDOFF 风险项） |
| 卡上文件名无法解析出时间 | 标题用同步时间，第二行注明「时间未知」 |
| 同一张卡被另一部手机绑走 | 下次连接时 `notPaired`，按 §7.1 引导重新配对 |
| 录音时长很长（数小时） | 列表时长按「X 小时 Y 分钟」显示；播放器进度条可拖动 |

### 7.3 数据边界

| 情况 | 处理 |
|---|---|
| 录音很多（上千条） | `List` 懒加载，按需从库里分页读 |
| 标题很长 | 列表单行截断；详情页完整显示 |
| 设备名为空 | 退回「录音卡 ·· 后 4 位」（**改进**：官方会显示空文案，OW §4） |
| 多卡同时有录音 | 列表混排，第二行标注卡名；不按卡分组（M1 没有文件夹） |
