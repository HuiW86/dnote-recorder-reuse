# 第 2 轮真机验收脚本（外部测试前，单卡）

**用途**　把 `device-todo.md` 里外部测试前必须做、并且一张卡就能做的项，排成一份照着做的脚本。用例的定义和通过线以 `test-spec.md` §3.4、§3.6.2 为准；本页只定顺序、用哪个构建、记录什么。
**结果**　填进 `evidence/v42-round2/README.md`（已预先写好每一项的判据），日志文件放在同一目录。
**日期**　2026-11-24，对应 main `d88af37`（PR #134 之后）。
**耗时**　约 3 小时，可以分两次做：A 部分用 TestFlight 构建（约 75 分钟），B 部分用 Xcode 装的 DEBUG 构建（约 95 分钟）。

## 为什么是这个顺序

- **先做升级（T-M1-56）**：后面「先不连卡」和 B 部分都要删掉 App 重装，手机上的旧库只能用一次。
- **写帧日志只有 DEBUG 构建有**（`app/Revive/Debug/TappedLink.swift`，导出 `card-debug.log`）。看命令字的项（T-M1-50 第 3 道检查、T-M1-57、T-M15-53、T-M15-54）都放在 B 部分；TestFlight 构建只有不含帧的诊断日志（设置 ›「导出诊断信息」）。
- **硬规则 2 相关的两项（T-M15-53、T-M15-54）放进本轮**：外部测试的构建里有「不要」，它会删卡上的文件，外部用户拿到之前必须在真卡上确认只在手机存好之后才删。
- **长录音期间做界面走查**：卡在录 30 分钟时手机空着，正好走 §9。

## 本轮不做（不阻塞本轮，但外部测试前还要补）

- 多卡 T-M1-55、换卡、P07「切换」（#8）：要另外两张卡。
- 非 v1.50 固件的提示（X1）：要拿到别的版本。

## 0. 准备（约 15 分钟）

- [ ] 卡充满电；Mac 上有 Xcode 和 Python 客户端（`client/`，见 `CLAUDE.md` 常用命令）
- [ ] **备份卡上录音**（`test-spec.md` §4）。先关掉 iPhone 的蓝牙，免得卡被手机连着：
  ```bash
  cd client && source .venv/bin/activate && python dnote.py pull --out ~/dnote-backup-round2
  ```
- [ ] 记下：手机型号、iOS 版本、卡的固件版本和电量。`sn` 只写 SHA-256 前 8 位（DEBUG 日志里的 `sha256:` 标记就是）
- [ ] iPhone 打开 设置 › 隐私与安全性 › **App 隐私报告**（用来看闻笺有没有联网，T-M1-50、T-M15-60）
- [ ] 从 main 打 **0.1.0 (7)** 上传 TestFlight，记下源码提交号。上一个上传的是 (6)（`evidence/v82-ble-cold-launch/`，基于 `86b898e`），之后 main 上改了 App 的提交有 88 个
- [ ] Xcode 里准备好**同一个提交**的 DEBUG 构建，B 部分要装

## A 部分：TestFlight 构建（约 75 分钟）

### A1. T-M1-56 从上一个 TestFlight 构建升级（10 分钟）

1. 手机上装 TestFlight 的 **(6)**（如果现在是 Xcode 装的 DEBUG，先在 TestFlight 里装回 (6)）
2. 在 (6) 里做出要保留的数据：已配对的卡、至少 3 条录音；(6) 里有的功能都用上（星标、重命名、文字稿或纪要，有就加）
3. 截图记下：录音条数、每条的标题和时长、已配对的卡
4. 在 TestFlight 里更新到 **(7)**，不删 App
5. 打开：条数、标题、时长、星标、文字稿都在；卡自动连上；能播放其中 2 条；诊断日志里没有 `library unavailable`

### A2. T-M1-53 长录音，同时做界面走查（35 分钟）

1. 用**卡上按键**开始录音，开始时间记下来。录 ≥ 30 分钟，中间有人说话
2. 录音的这段时间，在手机上做 #41 §9 走查（`product-spec.md` §9 第一组）：深色模式、最大号动态字体、VoiceOver 读一遍首页 / 详情 / 设备页 / 设置的按钮和状态、关掉网络再走一遍。每页截图
3. 用按键停止。App 在前台，看同步开始；结束后在设置里「导出诊断信息」，存为 `diagnostics-A2.log`
4. 吞吐 = 文件大小 ÷（日志里下载完成时间 − 开始时间），和约 24 KB/s 比较，偏差 ≤ 20% 算通过

### A3. T-M15-60 先不连卡（15 分钟，A 部分最后做）

1. 先在 P07 **解绑**这张卡，再删掉 App
2. 开始**录屏**，从 TestFlight 重新安装 (7)
3. P01 点「先不连卡，直接用」：**不弹**蓝牙权限框，直接进入标签栏
4. 用手机录一条 10 秒的、导入一个音频文件、对它点本机转写
5. 杀掉 App 再打开：直接进入标签栏
6. 录音卡页 →「添加录音卡」→ 回到 P01 → 点「继续」：**这时才**弹蓝牙权限框
7. 允许 → 配对卡 → 卡上的录音同步下来，手机录音和导入的都还在
8. 停止录屏。App 隐私报告里看闻笺：这一段没有网络访问（本机转写不联网）
9. 拒绝蓝牙那一支：删 App 重装，P01 点「继续」后选「不允许」，出现「需要蓝牙权限才能连接录音卡」，下面的「先不连卡，直接用」能进入标签栏

## B 部分：DEBUG 构建（约 95 分钟）

用 Xcode 把**同一提交**的 DEBUG 构建装到手机上。调试面板从页面右上角的瓢虫按钮（「调试」）打开。日志记下 App 收发的每一帧，面板关着时也记。每做完一项，打开面板「导出 card-debug.log」，存为 `card-debug-<项>.log`；导出后「清空」再做下一项。

**注意**：调试面板开着时 App 暂停自动同步，关上后恢复（`app/Revive/RootView.swift` 的 `DebugEntry`）。要看自动同步的项，操作时把面板关上，只在查「列表」「开关」和导出日志时打开。

写帧检查（每个日志都跑一次，**没有输出才算通过**）：

```bash
grep -nE '\] tx (93|94|B0|B1) ' evidence/v42-round2/card-debug-*.log
```

### B1. T-M1-50 飞行模式下的完整闭环（20 分钟）

1. 删掉 App，用 Xcode 重装 DEBUG；打开飞行模式，再单独打开蓝牙
2. 不注册：配对 → App 里开始、停止录音 → 卡上按键录一条 → 两条都同步 → 播放 → 分享导出 OGG（AirDrop 到 Mac，`ffprobe` 能读出时长）
3. App 隐私报告：闻笺没有任何网络访问
4. 导出 `card-debug-B1.log`，跑上面的写帧检查

### B2. T-M1-57 设置读回（10 分钟）

1. 设备页逐项切换：指示灯、马达、降噪及档位、增益、VAD、自动关机
2. 每切一项，在调试面板点「开关」读 `0x81`，日志里的读回值要和刚设的一致
3. 全部恢复原值。导出 `card-debug-B2.log`

### B3. T-M1-54 暂停与继续（5 分钟）

1. App 里开始录音，念「一」到「十」→ 暂停 10 秒 → 继续，念「十一」到「二十」→ 停止
2. 同步后播放：二十个数都在，暂停处没有丢字或重复；导出 OGG，用 `ffprobe` 看时长和 App 显示的一致

### B4. T-M1-51 后台与锁屏自动同步（20 分钟）

1. 卡上按键录一条约 10 秒的，再按键停止。前台、后台（回到主屏幕）、锁屏各做 3 次，共 9 次
2. `card-debug.log` 每行带 `[fg]` / `[bg]` / `[lock]`：每次从录音停止到同步开始的时间 ≤ 10 秒
3. 导出 `card-debug-B4.log`，把 9 次的停止时间、同步开始时间填进结果表

### B5. T-M1-52 同步中断线（10 分钟）

1. 卡上录一条 ≥ 5 分钟的，停止后同步一开始，就把卡带到够远的地方（或放进金属盒），直到日志里出现断开（`link`）
2. 等 1 分钟再带回：自动重连，同步完成
3. 调试面板「列表」：卡上每个文件都标「✓ 已存手机」；App 列表里这一条只有一份，时长对
4. 导出 `card-debug-B5.log`

### B6. T-M15-53、T-M15-54：「不要」只在手机存好之后删卡（硬规则 2，20 分钟）

只用测试录音。卡上文件列表用调试面板的「列表」看，不用 Python 客户端（卡同一时间只连一台）。

1. T-M15-53：App 开始录音，日志里记下录音中拿到的文件名（`0x51` 回包）→ 停止 → 同步后和「列表」里的文件名对照。卡上按键开始再做一遍；录音中断开再重连（文件名来自 `0x56`）再做一遍。三次都要逐字一致
2. T-M15-54：
   - 录一条，停止后点「不要」；同步完成前打开面板点「列表」：卡上**还在**（打开面板会暂停自动同步，看完关上让它继续）；同步完成后再看：没了。日志里这个文件的 `70` 下载在 `91` 删除**之前**
   - 设置 › 最近删除里找到这条，能完整播放
   - 再录一条，点「不要」后 5 秒内「撤销」：同步后卡上还在，列表里有
   - 再录一条，点「不要」后马上把卡带离到断开，1 分钟后带回：断开期间卡上还在，重连同步后才删
   - 全程没有别的文件被删：「列表」的文件数前后对得上
3. 导出 `card-debug-B6.log`；另外用下面的命令把 `91` 前后的行摘出来，贴进结果：
   ```bash
   grep -nE '\] tx (70|91) ' evidence/v42-round2/card-debug-B6.log
   ```

### B7. T-M15-58 Opus 帧头统计（#66，10 分钟）

1. 关掉 iPhone 的蓝牙，在 Mac 上重新 `pull` 一次，拿到 A2 的长录音：
   ```bash
   cd client && python dnote.py pull --out ~/dnote-backup-round2
   ```
2. 选 3 个 `.raw`：1 分钟以内、A2 那条 30 分钟以上、按键发起的一条（至少一条有人说话、一条基本安静）
   ```bash
   python dnote.py toc <三个 .raw 文件> > ../evidence/v66-opus-toc/toc-v1.50.txt
   ```
3. 每个文件都是 `matches 20 ms mono: yes` 才算通过；有 `NO` 时按 `evidence/v66-opus-toc/README.md` 的判据表处理
