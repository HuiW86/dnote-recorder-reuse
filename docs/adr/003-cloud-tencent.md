# ADR-003：云厂商选腾讯云

**日期**　2026-11-06
**状态**　Accepted
**来源**　#26（父 issue #10）

## 背景

- 部署在国内云厂商已定（`backend-design.md` §2.4）。
- 需要：云服务器、PostgreSQL、对象存储、ASR（录音文件识别 + 实时识别，要求区分说话人）、大模型、短信（账号登录用）。
- ASR 的最终选型在 M2 前置任务中实测（#12），接口做成可替换（§4.5），所以云厂商不锁死 ASR。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **腾讯云** | COS、云数据库 PostgreSQL、ASR（录音文件与实时）、混元大模型、短信都在一家，一个账号、一套计费 | ASR 说话人区分的效果要实测 |
| 阿里云 | 同样产品齐全；通义和 Paraformer 在中文 ASR 上口碑好 | — |
| 火山引擎 | 豆包语音和大模型性价比高 | 通用云产品（数据库、对象存储）成熟度稍弱 |

用户选择腾讯云。

## 决定

基础设施（服务器、PostgreSQL、对象存储 COS、短信）用腾讯云。ASR 和大模型默认也用腾讯云，但 M2 的 ASR 选型实测中可以选别家，通过可替换接口接入。

## 后果

- 正面：一个账号管理全部资源，计费和权限集中。
- 负面：
  - 服务器在国内、对外提供域名访问，**域名需要 ICP 备案**，M2 开始前要办完（M1 不需要后端，不受影响）。
  - 短信要先申请签名和模板，个人主体能否申请需核实；不能申请时，M2 先上邮箱登录（§4.3 已把邮箱列为后备）。
- 反悔成本：存储、数据库都是通用协议（S3 兼容、PostgreSQL），迁移成本中等；在 M2 之前改决定基本无成本。
