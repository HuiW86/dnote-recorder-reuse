# ADR-008：App 显示名定为「声笺」，启用正式图标

**日期**　2026-11-09
**状态**　Accepted
**来源**　#42（TestFlight 发布）；接续 ADR-005

## 背景

- ADR-005 用代号 Revive 作显示名，正式名留到上架前再定。
- 首次上传 TestFlight 需要 App 图标，App Store Connect 里的 App 名称也会被测试员看到。用户决定在首个 TestFlight 构建就用正式名和图标，避免测试员看到改名。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **显示名改为「声笺」，配用户提供的图标** | 测试员从第一个构建起就看到正式名；以后不用再改 | 未做商标检索；App Store Connect 里名称可能已被占用 |
| 继续用 Revive，上架前再改 | 不用现在决定 | TestFlight 用户会经历一次改名；仍要先做一个图标 |

## 决定

- 用户可见的名称一律用 **声笺**：`CFBundleDisplayName`、App 内文案（关于页、隐私说明、权限引导、诊断信息）。
- 图标用用户提供的设计（原图 `design/logo.png`，1254 px；App 内用缩到 1024 px 的版本）：红底、倾斜的白色卡片上镂空三条声波，不含对方 logo 或商标元素（ADR-005 的约束不变）。
- 工程名、Swift 模块名、Bundle ID（`com.huiw86.revive`）保持 Revive 不变，理由同 ADR-005：Bundle ID 上传后不能改，用中性代号。
- App Store Connect 里的 App 名称填「声笺」；若被占用，用「声笺录音」之类的变体，显示名仍是「声笺」。

## 后果

- 正面：首个 TestFlight 构建即是正式名和图标。
- 负面：没有做商标检索。转正式上架（ADR-004 的触发条件）前要补检索；如有冲突，再新开 ADR 改名。
- 反悔成本：低。改显示名、文案和图标都不影响 Bundle ID 和用户数据。
