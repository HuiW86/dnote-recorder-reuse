# 多语言界面评估

**日期**　2026-11-21
**来源**　#75 七「多语言界面：上架前看一次」；`beanpod-evaluation.md` §5（「上架前各看一次」）；`product-spec.md` §10
**结论**　建议外部测试和首次上架都只做简体中文，不翻译；英文界面等用户决定要不要面向海外再做。要做时分两步：第一步把文案收进 String Catalog，界面看起来不变；第二步才翻译。
**决定**　用户 2026-11-21：先只做简体中文。第一步（String Catalog）也暂不排期，等决定加语言时再做；是否面向海外到时再定。

---

## 1. 现状（按 main `4e7dba5` 统计）

- 工程声明的开发语言是简体中文（`app/project.yml` 的 `developmentLanguage: zh-Hans`、`CFBundleDevelopmentRegion: zh-Hans`）。仓库里没有 `Localizable.xcstrings`，也没有 `.strings` 或 `.lproj`。
- 文案全部直接写在 Swift 代码里。下表是含中文的字符串字面量，已去重，不含注释：

| 位置 | 条数 | 字数 | 说明 |
|---|---|---|---|
| App 目标 `app/Revive/`（不含 Debug） | 359 | 约 5,200 | 界面文字。其中约 370 处是 `Text("…")`、`Button("…")` 这类写法，Xcode 能自动收进 String Catalog；约 30 处带插值（如「第 \(n) 条」），也能收，但要逐条核对 |
| `AppModel` | 180 | 约 2,200 | Toast、错误提示、状态文字、导出文件里的标题。类型是 `String`，Xcode **不会**自动收，要改成 `String(localized:)` |
| `Assistant` | 179 | 约 2,000 | 一半是发给 AI 服务的提示词（9 段多行提示词约 2,400 字，另有场景名、栏目名、改写类型）；其余是错误提示 |
| DEBUG 调试页 | 68 | 约 660 | 不随正式版发出，不用翻译 |
| 合计（随正式版发出） | 约 700 | 约 9,300 | |

- 权限说明 3 条在 `project.yml` 的 `info.properties` 里（蓝牙、麦克风、语音识别），翻译要另建 `InfoPlist.xcstrings`。
- 日期：录音列表的「11月7日 14:02」由 `RecordingText` 用 `String(format: "%d月%d日 ")` 拼出来；录音默认标题是 `yyyy-MM-dd HH:mm`，存在数据库里。`product-spec.md` §10 要求跟随系统地区，目前没有做到。
- 内容语言写死为中文，和界面语言是两回事：
  - 本机转写和录完自动整理都用 `zh-CN`（`RecordingDetailModel.transcribe`、`AutoProcessor`）；
  - 纪要、改写、提问的提示词是中文，要求模型用中文回答；
  - 单词分级（X20）是给说中文的人学英语用的；
  - 知识库提问挑选纪要时按中文两个字切词（`QuestionSources`），英文按词切，已经能处理英文。
- 文档和发布材料都只有中文：隐私政策（App 内 P11 和公开版）、TestFlight 说明、审核备注。

## 2. 为什么现在不做

- **用户是谁**：D·NOTE 官方 App 和它的服务都是中文，后端规划也部署在国内云厂商（`backend-design.md`）。闻笺首先要接住的是这批卡的用户（`CLAUDE.md` 定位），目前没有证据显示有不读中文的用户。
- **翻译只是一小部分**：英文界面不只是 700 条文案。内容语言（转写语言、纪要用什么语言写、提示词）要先定规则：例如界面是英文、录音是中文时，纪要用哪种语言？这是产品决定，不是翻译。
- **成本持续存在**：之后每个 PR 改文案都要同时改英文，真机检查和截图也要多做一套。现在一周要合好几个改文案的 PR（#109～#117），这笔成本不小。
- **外部测试前的事还没做完**：真机检查（`device-todo.md`）、多卡 #8、#66、隐私政策托管。多语言不在这条路上。

## 3. 要做时怎么做

### 第一步：收进 String Catalog（界面看起来不变）

可以在决定翻译之前单独做，好处是以后加语言不用再碰代码，`product-spec.md` §10 要求的「不在代码里写死」也就做到了。

1. 新建 `app/Revive/Localizable.xcstrings`，源语言简体中文。用 Xcode 的「从代码提取」把 `Text("…")` 这类写法收进去（约 370 处）。
2. `AppModel` 和 `Assistant` 里给用户看的文字改用 `String(localized:)`，放进 ReviveKit 各模块自己的 String Catalog（Swift Package 的资源，`defaultLocalization: "zh-Hans"`）。约 180 + 90 条。
3. **提示词不进 String Catalog**：它们决定模型输出，跟内容语言走，不跟界面语言走。
4. 权限说明改到 `InfoPlist.xcstrings`。
5. 日期改用 `Date.FormatStyle`；`11月7日` 这类拼接全部换掉。录音默认标题已经存进数据库，不改旧数据。
6. 加一条静态检查（可以并进 `check-theme.sh` 的做法）：App 目标和 `AppModel` 里不能再出现直接拼进 `String` 的中文。没有这条检查，过几周就会有新的写死文案。

估计：两三个 PR，大部分是机械改动。风险是插值文案改成本地化键时漏改或格式错，靠现有的界面测试和一次界面走查兜底。

### 第二步：翻译（以英文为例）

1. 约 700 条、9,300 字的界面文案译成英文。beanpod 用 String Catalog 加一个同步脚本（`scripts/i18n-sync.py`）检查缺译，可以参照。
2. 先定内容语言规则，再动代码：转写语言让用户选（默认跟随系统），纪要和改写用录音本身的语言写，提问用提问的语言答。提示词要能按语言切换。
3. 英文比中文长，按钮、标签栏、Toast 都要重新看排版；截图脚本多跑一遍。
4. 隐私政策、TestFlight 说明、App Store 页面出英文版。
5. 商标规则（硬规则 5）在英文描述里同样适用：只能写 "for D·NOTE voice recorder cards" 这一类说法。

## 4. 要用户决定的（2026-11-21 已决定：先只做简体中文，见文首）

| 问题 | 选项 |
|---|---|
| 首次上架是否只做简体中文 | 建议是。`features.md` O1a 现在就写着「界面先只做简体中文」，不用改范围 |
| 第一步什么时候做 | 现在做：以后加语言便宜，文案也集中可查；缺点是两三个 PR 的工作量，会和正在改文案的 PR 冲突。等决定翻译时再做：现在不花时间 |
| 是否面向海外 | 是的话再定第二步，并在 `features.md` 新增一项 |

## 5. 顺带发现的问题

- 麦克风权限弹窗的文字（`project.yml` 的 `NSMicrophoneUsageDescription`）还是「录音卡不在身边时，用手机的麦克风录音」。#116 改了 P12 的说明，但这一句漏了，没有卡的人看到会奇怪。本次一起改为「没有录音卡或录音卡不在身边时，用手机的麦克风录音；录音只保存在这部手机上」，与 P12 一致。
