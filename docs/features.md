# 功能清单与范围对照表

**用途**　把官方 App 的功能（`official-app-analysis.md` §2 的 A1～O1）逐条落到里程碑 M1～M4，或标明不做；是阶段 1 其余交付物（ADR、`prd.md`、`test-spec.md`）的范围基线
**范围依据**　`backend-design.md` 的 C 方案（接近全复刻，去掉电子名片）及 §2.2 不覆盖项

## 0. 定位与推进顺序（2026-11-16）

**定位**　起点是 D·NOTE 录音卡的用户；目标是录音和声音内容的工作台，面向三类人：

| 用户 | 要什么 | 主要落在 |
|---|---|---|
| 手里有录音卡的人（D·NOTE，以后还有 Anker 录音豆、得到录音卡） | 卡能用，录音安全到手机，不依赖厂商的 App 和云 | M1、M1.5、M3、M6 |
| 想把录音变成文字和纪要的人 | 文字稿、总结、待办、提问；自己的服务或我们的后端都行 | M1.5 的本机转写、M2、M4 |
| 用声音做内容的人 | 导入播客和视频、改写成稿、语音输入、Mac 上用 | M4 的改写、M5 |

**推进顺序**　① M1 验收与外部测试（#42，含 #66）→ ② 界面改版第一步（#74）→ ③ M1.5（#70）→ ④ M2 里不依赖后端的一半（文字稿与纪要界面、X11 用户自配服务）→ ⑤ 其余到时再排。里程碑编号不代表先后，以这里为准。

## 5. 定义

**优先级**
- P0：缺了这个里程碑就不能验收
- P1：本里程碑应交付，必要时可顺延一个里程碑
- P2：可顺延，不影响验收

**状态**：planned（已排期）→ in-progress（有 PR 在做）→ done（已合并）→ verified（按 `test-spec.md` 在真机上验证通过）；deprecated 表示已取消。

**测试覆盖**：填 `test-spec.md` 的用例编号（省略前缀 `T-M1-` 之后的部分时，同一格内沿用前一个前缀）。M2～M4 的用例在进入里程碑时补。

**工程规格对应**（`prd.md`）：

| 条目 | `prd.md` 章节 |
|---|---|
| A1、A3a、A4a、B1、X1 | §2 设备层接口契约 |
| A2 | §3 配对状态机 |
| C1、D1a | §4 同步状态机、§5 本地数据模型 |
| D1b、E1b、X6～X10 | §5.4～§5.7（`recording_mark`、`discard_request`、`transcript`，以及 `trashed_at`、`title` 的用法） |
| E1a | §1 分层（Player / Exporter）、§5.2 |
| K1、A4b、F1、G1、G2a、O1b、X2 | §7.2 接口分组、§8 后端数据模型 |
| X3、N1、I1 | §7.5 同步模型 |
| C2、H1、G3 及其余 M3/M4 条目 | §7.2（模块级），进入对应里程碑时细化 |
